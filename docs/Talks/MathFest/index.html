Main Question

Can a surface group act properly on a locally compact product of trees?

Long-Reid Group

Let \(\Gamma=\langle a,b\mid [a,b]^2=1\rangle\) — the fundamental group of an orbifold which is a torus with a cone point of order 2. We get a representation of \(\Gamma\) into \(\PGL_2(\Q(t))\) by taking

\[ \left\langle \begin{pmatrix} t & 0 \\ 0 & 1 \end{pmatrix}, \begin{pmatrix} t^2+1 & 2 \\ t & 1 \end{pmatrix} \right\rangle \leq \PGL_2(\Z[t,\tfrac{1}{t},\tfrac{1}{t-1}]) \]

Specializing \(t\in\Q\), we obtain a subgroup of \(\PGL_2(\Q)\). This determines a proper action on a product of trees if and only if the representation is faithful and \(\Gamma_t\cap \PGL_2(\Z)\) is finite.

The particular case \(t=9\) gives a surface group acting on the product of the 2-adic and 3-adic trees.

Normalized into SL2: a = (1/3)diag(9,1), b = (1/8)[[82,2],[9,1]]; all entries in Z[1/6]. The relator [a,b]^2 = -I makes ±I unavoidable torsion, so a properness witness must be a non-central integer matrix.

Computation

Suppose that \(G\) is a finitely generated group, and \(C\colon G\to \R_{\geq 0}\) is a cost function.

For example, the cost might be a norm on the group, or the size of the denominator of an element.

We want to somehow efficiently navigate the group to find elements with small cost.

Cayley graph of Γ₉ in the hyperbolic plane. Γ₉ IS discrete in SL₂(R) — it is the cocompact Fuchsian group of the torus-with-cone-point orbifold, from the explicit hyperbolic rectangle; the open question is properness on the trees, i.e. whether Γ₉ ∩ PGL₂(Z) is finite. Next step lifts each element to its cost: e₂ + e₃ where the cancelled matrix is N/(2^e₂·3^e₃), computed in exact Z[1/6] arithmetic. Cost climbs as you walk out, so the search is hunting for a distant element that has come back down to height 0. Phone remote: Play/Pause toggles the lift. Keys in the frame: space, R.

Breadth-First Search

Explore the Cayley graph layer by layer.

\[ \mathcal{B}_0 = \{id_G\}, \qquad \mathcal{B}_{k+1} = \mathcal{B}_{k}\cdot S \]
  • Pros: Guaranteed to find a solution if one exists.
  • Cons: Each successive iteration takes \(|S|\) times longer than the previous one.

Greedy Algorithms

Always extend the "best" candidate according to the cost function \(C\).

\[ g_0=id_G, \qquad g_{n+1} = g_n s_i, \text{ where } s_i \in S \text{ minimizes } C(g_ns) \]
  • Pros: Extremely fast — we only keep track of one element at a time.
  • Cons: Nearly guaranteed to fail.

Beam Search

We first choose a beam width \(W\). We initialize the beam \(B_0=\{I\}\).

Given the current beam \(B_n\), we first build the set \(B_{n+1}'=B_n\cdot S\), the extended beam. We then prune this set to \(B_{n+1}\) by taking the top \(W\) elements with the smallest cost. Let \(\mathsf{WMin}(X)\) denote this operation.

\[ B_{n+1} = \mathsf{WMin}(B_n\cdot S) \]
  • Pros: An excellent compromise of speed and success rate. Each iteration takes a constant amount of time.
  • Cons: If the minimal length of a successful word is \(k\), we will require at least \(k\) iterations.

FlashBeam Search

We first choose a beam width \(W\) and a flash size \(F\). We initialize the flash \(F_0\) to consist of the generating set, and set \(B_0 = \{I\}\).

\[ B_{n+1} = \mathsf{WMin}(B_n\cdot F_n), \qquad F_{n+1} = \mathsf{FMin}(F_n\cdot S) \]
  • Pros: This can find a solution of length \(k\) in \(\log k\) iterations.
  • Cons: A large flash size slows down the algorithm.

FlashBeam Search

We can think of the flashbeam search as exploring the Cayley graph of the group, but the generators vary as we explore it!

This can be useful in finding "optimal" generators for a group, such as computing Dirichlet domains.

An integer matrix in the Long‑Reid group

The length 82 word

\[ \begin{aligned} & a^{2}\,b\,a^{-2}b^{-1}\,a\,b\,a^{2}b^{-1}a^{-1}b^{-1}\,a^{2}\,b\,a^{-1}\,b\,a^{2}b^{-1} \\ & a^{-1}b^{-1}\,a\,b\,a\,b^{-1}\,a\,b\,a^{-1}\,b\,a^{2}b^{-1}\,a^{3}\,b\,a^{-2}b^{-1} \\ & a\,b^{-1}a^{-2}\,b^{2}\,a\,b^{-1}a^{-2}\,b\,a^{-1}b^{-1}\,a\,b^{-1}a^{-2}\,b\,a\,b^{-1} \\ & a^{2}\,b\,a^{-1}\,b\,a\,b^{-1}\,a\,b\,a^{-1}\,b\,a^{2}b^{-1}\,a^{3}\,b\,a^{-2}b^{-1} \end{aligned} \]

evaluates to the infinite-order integer matrix

\[ \begin{pmatrix} -646279884109511971664607 & 6162511442411222450262052 \\ -4193268331567764626734 & 39984323680432243295081 \end{pmatrix} \]
This is the witness from Brody, "An improper surface group action" (arXiv:2512.19760): the length-82 word above, evaluated in a = (1/3)[[9,0],[0,1]], b = (1/8)[[82,2],[9,1]]. Verified here: entries exactly integral, det = 1, trace = −606295560429079728369526 (so infinite order). The racer on the next slide plays exactly this word.

Applying to Kleinian Groups

The new workflow

  • Describe the mathematical object; get a working interactive tool the same afternoon.
  • Iterate by conversation: "make the faces translucent," "animate the side pairing," "add a Cayley graph."
  • The bottleneck moves from programming back to mathematics.

Let's use one.

Step-through tutorial (driven from the phone remote): Poincaré ball → one isometry → bisector wall → Dirichlet domain → face pairings → Cayley graph. See poincareTutorial/TUTORIAL.md for the step plan.

Conclusions

  • The math inside AI systems — search, scoring, optimization — is already ours. Point it back at mathematics.
  • Computation finds the phenomena; we still get to find the reasons.
  • And when an idea is interactive, more of it survives the trip from one mind to another.
