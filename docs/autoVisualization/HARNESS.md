# AutoViz — daily visualization harness

One page per day: a self-contained, interactive HTML visualization of a phenomenon in
geometry, group theory, topology, dynamics, number theory, combinatorics, or nearby.
This file is the complete spec for the daily scheduled run. Follow it exactly.

Directory layout:

```
docs/autoVisualization/
  HARNESS.md      ← this spec
  index.html      ← gallery (reads manifest.js; do not restructure)
  manifest.js     ← window.AUTOVIZ array, newest first
  futureVisualizations.md ← rolling plan for the next 5+ pages (rules inside)
  days/           ← one HTML file per day
```

## Daily procedure

1. **Pick the topic.** Take the TOP entry of the queue in `futureVisualizations.md`.
   Deviate only for a clearly better idea that day (note the swap in the commit
   message), and cross-check `manifest.js` that the topic isn't already covered.
2. **Build the page** at `days/YYYY-MM-DD-<slug>.html` (today's date, short kebab slug).
3. **Register it:** prepend one entry to `window.AUTOVIZ` in `manifest.js` (format below).
4. **Replenish the plan:** remove the entry you built from `futureVisualizations.md`
   and top the queue back up to **at least 5** upcoming ideas, following the rules in
   that file — rooted in this site's interests (see Inspiration below), varied in area,
   each with its planned interaction spelled out.
5. **Verify** (below), then **commit**.

## Page contract

- Fully self-contained: inline CSS and vanilla JS, rendering via canvas / SVG / WebGL.
  **No network requests, no CDNs, no external libraries.** The page must work offline.
- Dark theme, in the family of the gallery (`index.html`): near-black background,
  glassy panels, one restrained accent color. Responsive; works at 900px wide.
- Required elements:
  - An `<h1>` title and a short paragraph (2–4 sentences) stating the actual
    mathematics — name the theorem or phenomenon precisely, no hand-waving.
  - **Every page must be interactive or dynamic — a static picture is a failed run.**
    At minimum one *meaningful* control (slider, preset select, drag, click/hover
    inspection) that changes the mathematics shown, not just cosmetics; prefer live
    motion too — animation driven by the mathematics (flows, orbits, cascades),
    not decorative easing.
  - A back link to `../index.html` at the top.
  - Footer line: `AutoViz · YYYY-MM-DD · generated by Claude (Fable 5)`.
- The mathematics must be right. Compute real objects (exact/rational arithmetic where
  feasible), and sanity-check at least one numeric fact of the construction in the
  console or by hand before shipping. Target: a page a mathematician would linger on.
- Keep it performant: cap recursion/particle counts; no unbounded loops.

## Inspiration — tie it to this site

The gallery lives inside Nic Brody's site, and pages should resonate with the
mathematical world already there. When choosing or queueing topics, skim what exists:

- `docs/GeometryofLinearGroups/` — Algebraic / Geometric / Arithmetic sections and their
  Tools: Zariski closures, quaternion algebras, Fuchsian and Kleinian groups, the Riley
  slice, Dirichlet domains and Poincaré certificates, Markov starscapes on character
  varieties, Cayley-graph Laplacians, space groups, braid groups and Burau.
- `docs/topology/knotTheory/` — knot mosaics, knot energies.
- `docs/graphics/`, `docs/mathArt/`, `docs/Talks/` — Penrose tilings, Turing patterns,
  hyperbolic tessellations, orbifolds.

Recurring interests to draw on: linear groups over ℚ, arithmetic subgroups and lattices,
hyperbolic geometry in dimensions 2–3, discreteness certificates, character varieties,
continued fractions and Diophantine approximation, knots and braids, Cayley graphs,
tilings and Coxeter groups — with exact/integer arithmetic behind the pictures wherever
feasible. Do NOT duplicate an existing site tool: build something adjacent that
complements it, and feel free to mention (not link-depend on) a related tool.

## Manifest entry format

Prepend (newest first) to the array in `manifest.js`:

```js
{
  date: "YYYY-MM-DD",
  file: "YYYY-MM-DD-slug.html",          // in days/
  title: "Title Case Name",
  area: "Area of mathematics",
  blurb: "One or two sentences: the phenomenon and the theorem behind it."
}
```

## Verification (required, headless — never ask the user to check)

1. `preview_start {name: "autoViz"}` (launch config, port 8766, no-store server), then
   navigate to `http://localhost:8766/docs/autoVisualization/days/<file>`.
2. `read_console_messages` — zero errors.
3. Screenshot to confirm it actually renders (beware all-black WebGL screenshots:
   if black, read pixel values via `javascript_tool` before concluding failure).
4. Gotcha: `requestAnimationFrame` can be frozen in the preview pane — if the page
   animates, drive one frame manually via `javascript_tool` to verify, don't wait.
5. Load `../index.html` and confirm the new card appears at the top of the gallery.

## Git

- Commit **only** files under `docs/autoVisualization/` with message
  `autoViz: YYYY-MM-DD <title>`.
- Do NOT push. (Change this line to "Push after committing." to auto-deploy to GitHub Pages.)

## Never

- Modify anything outside `docs/autoVisualization/`.
- Use external CDNs, fonts, or fetches.
- Repeat a topic already in the manifest, or duplicate an existing site tool.
- Ship a page with no interaction and no dynamics.
- Leave `futureVisualizations.md` with fewer than 5 upcoming entries.
- Skip verification or commit a page with console errors.
